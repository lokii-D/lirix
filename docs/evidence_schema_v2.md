## 📡 Typed envelope snapshot

`evidence_v2` is the **per-layer** companion to **`security_trace`** (the narrative timeline). Pair reads with [**`docs/audit_path_map.md`**](audit_path_map.md) so automation joins stay unambiguous.

---

Lirix provides a typed v2 evidence envelope in `evidence_v2` while preserving additive compatibility fields.

Single audit entrypoint (architecture → code → tests → evidence → CI): **[`docs/audit_path_map.md`](audit_path_map.md)**.

Schema:

- `schema_version`: always `2.0`
- per-layer evidence objects generated by `build_layer_evidence_v2`
  - `layer`
  - `status`
  - `details`

Runtime mode (single-stack):

- `rpc_evidence_mode=v2_only`: `rpc_evidence_v2` only
- migration aliases (`legacy`, `v2_dual`) are coercion-only compatibility inputs and are normalized to `v2_only` during config parsing

---

## 🛡️ Compatibility policy

- additive-only: existing payload keys are preserved
- mode semantics are single-stack at runtime; migration aliases are input-compatibility only

---

## 🔗 Relationship to other evidence surfaces

`evidence_v2` is an additive, typed layer-evidence envelope. It does **not** replace:

- `security_trace` (full step timeline)
- `validation_session` (session lifecycle + timeline)
- `replay_bundle` (integrity + closure)
- `forensic_bundle` (fail-focused extraction)

Recommended joins:

- join by `security_trace.correlation_id`
- join by `validation_session.session_id`
- validate integrity using `verify_replay_bundle(replay_bundle)`

---

## 📐 Minimal shapes (by entrypoint)

- `validate_only(...)`:
  - `evidence_v2.l1`, `evidence_v2.l2`, `evidence_v2.l3`
- `simulate_only(...)`:
  - `evidence_v2.l4`, `evidence_v2.l5`
- `validate_and_simulate(...)` / `async_validate_and_simulate(...)`:
  - `evidence_v2.l4`, `evidence_v2.l5`, `evidence_v2.policy`

All shapes are **additive-only**; consumers must tolerate extra keys inside `details`.
